description: How to run npx jest in a .claude/worktrees/* checkout that has no node_modules of its own
metadata:
  type: feedback
---

Worktrees under `.claude/worktrees/` frequently have no `node_modules` (and sometimes no `package-lock.json` at all — this repo has none tracked). The main checkout has `node_modules` installed. Symlink it in for the session, then remove the symlink once verification is done: `ln -s <main-checkout>/node_modules <worktree>/node_modules` ... `rm <worktree>/node_modules`.

**Why:** A bare npm install duplicates 1.5GB+ and is slow; the sandbox also blocks writing to anything under the main checkout (including its shared `.git/info/exclude`), so a symlink is the only fast, non-destructive option.

**How to apply:**
- A symlink literally named `node_modules` is NOT matched by a `.gitignore` entry of `node_modules/` (trailing slash requires the entry to be a real directory in git's eyes) — `git status` shows it as untracked (`??`). Do not leave it in place at the end of a session; remove it before finishing so nothing risks being accidentally `git add`ed.
- Do not attempt to fix this by editing `.git/info/exclude` in the main checkout — the worktree sandbox refuses commands that touch paths outside the current worktree, and it would violate "do not modify anything under the main checkout" if that constraint is in play.
- The jest binary resolves fine through the symlink (`node_modules/.bin/jest`), so no other setup is needed.
